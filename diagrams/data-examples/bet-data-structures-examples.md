# Bet Data Structures Examples

This document provides concrete examples of bet data structures with and without promotion support, based on the actual implementation in `ProcessBetQueue` and `PromotionBetInterceptor`.

## Overview

The bet processing system transforms data through several stages:

1. **Incoming Payload** - Raw bet data from client
2. **API Bet Info** - Formatted for game management API
3. **Bet Record** - Stored in bets collection
4. **Bet Log** - Stored in bet logs collection

The `PromotionBetInterceptor` enhances these data structures when promotion features are used.

## 1. Incoming Bet Payload

This is the raw bet data that gets queued in `playerInGame.betQueue`.

### Without Promotion

```javascript
{
  "amount": 100,
  "betChoice": "red",
  "roundId": "round_12345",
  "mode": "normal",
  "time": "2024-01-15T10:30:00.000Z",
  "clientSeed": "client_seed_abc123",
  "clientSentTime": "2024-01-15T10:29:58.500Z",
  "receivedTime": "2024-01-15T10:30:00.100Z"
}
```

### With Promotion

```javascript
{
  "amount": 100,
  "betChoice": "red",
  "roundId": "round_12345",
  "mode": "normal",
  "time": "2024-01-15T10:30:00.000Z",
  "clientSeed": "client_seed_abc123",
  "clientSentTime": "2024-01-15T10:29:58.500Z",
  "receivedTime": "2024-01-15T10:30:00.100Z",
  "usePromotion": true,
  "promotionId": "promo_winter2024"
}
```

**Key Differences:**

- Promotion payloads include `usePromotion: true`
- Promotion payloads include `promotionId` field
- These fields trigger `PromotionBetInterceptor.shouldIntercept()` to return `true`

## 2. API Bet Info

Generated by `formatApiBetInfo()` method, sent to game management API.

### Without Promotion

```javascript
{
  "amount": 100,
  "gameId": "crash_game_v1",
  "gameRoundId": "round_12345",
  "choiceId": 1, // mapped from betChoice "red" via definition.choicesMapper
  "clientSentTime": "2024-01-15T10:29:58.500Z",
  "metadata": {
    "mode": "normal"
  }
}
```

### With Promotion (Enhanced by PromotionBetInterceptor)

```javascript
{
  "amount": 100,
  "gameId": "crash_game_v1",
  "gameRoundId": "round_12345",
  "choiceId": 1,
  "clientSentTime": "2024-01-15T10:29:58.500Z",
  "metadata": {
    "mode": "normal",
    "usePromotion": true,
    "promotionId": "promo_winter2024"
  }
}
```

**Enhancement Process:**

- `PromotionBetInterceptor.transformEventData("enhanceBetInfo", context)` adds promotion data to metadata
- Original metadata is preserved and extended

## Data Transformation Flow

```
Client Payload → API Bet Info → Game Management API
      ↓
Bet Record → MongoDB bets collection
      ↓
Bet Log → MongoDB bet logs collection
```

### Interceptor Enhancement Points

1. **shouldIntercept()** - Checks `payload.usePromotion` and `payload.promotionId`
2. **beforeEvent()** - Processes promotion deduction before bet placement
3. **transformEventData()** - Enhances data structures with promotion fields
4. **afterSuccessEvent()** - Creates promotion ticket after successful bet
5. **afterFailureEvent()** - Rolls back promotion after failed bet

## API Integration Points

### Promotion API Calls

```javascript
// Before bet placement
const deductDto = {
  operatorId: player.session.operatorId,
  siteName: player.session.siteName,
  playerId: player.session.playerId,
  promotionId: promotionData.promotionId,
  quantity: 1,
};
await gamePromotionApiClient.deductBonusItem(deductDto);

// After successful bet
const ticketDto = {
  playerId: player.session.playerId,
  operatorId: player.session.operatorId,
  gameId: this.definition.id,
  gameRoundId: bet.roundId,
  appType: 1,
  betAmount: bet.amount,
  winAmount: 0,
};
await gamePromotionApiClient.createPromotionTicket(ticketDto);

// After failed bet (rollback)
const rollbackDto = {
  operatorId: player.session.operatorId,
  siteName: player.session.siteName,
  playerId: player.session.playerId,
  promotionId: bet.promotionId,
  quantity: 1,
};
await gamePromotionApiClient.rollbackBonusItem(rollbackDto);
```
